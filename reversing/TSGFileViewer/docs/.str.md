Based on the analysis of the provided C# scripts, here is the documentation for the file formats handled by the code. The primary container is the **STR** format, which houses various resource types including **SimGroups**, **MetaModels**, and others.

All formats generally appear to use **Big-Endian** byte order (common for consoles like PS3/Xbox 360 of that era), as evidenced by the frequent use of `ReadInt32BigEndian()` and `ReadSingleBigEndian()`.

# 1. Container Format: EA Stream File (.str)

**Handled by:** `Scripts/EAStreamFile.cs`

**Extension:** `.str`

**Endianness:** Big-Endian

The `.str` file acts as a container (archive) for streaming resources. It contains a header, a list of sections, and then the raw data for those sections.

## Header Structure

Located at offset `0x00`.

| Offset | Type | Name | Description |
| --- | --- | --- | --- |
| 0x00 | `char[4]` | Magic | Fixed signature: `SToc` |
| 0x04 | `int32` | Version | Format version. |
| 0x08 | `byte` | nSections | Number of stream sections in the file. |
| 0x09 | `byte` | PlatformID | Target platform identifier. |
| 0x0A | `byte[2]` | Padding |  |
| 0x0C | `int32` | pStreamFile | Offset to the `StreamFile` metadata struct. |
| 0x10 | `int32` | pSectionArr | Offset to the array of Section descriptors. |

## StreamFile Struct

Located at `pStreamFile`.

| Type | Name | Description |
| --- | --- | --- |
| `uint32` | GUID | Unique ID (SDBM Hash of filename usually). |
| `ptr` | FileName | Offset to null-terminated string relative to a pointer offset. |
| `byte` | nParents | Number of parent stream files. |
| `byte` | nForceLoad |  |
| `byte` | nSections | Duplicate of header nSections. |
| `byte` | Flags |  |
| `int32` | Unk |  |
| `int32` | pRelatives | Offset to related file info. |
| `int32` | pSectionInfo | Offset to section info. |

## Section Descriptor

Located at `pSectionArr`. There are `nSections` entries.

| Type | Name | Description |
| --- | --- | --- |
| `uint32` | MemPolicyID | Memory allocation policy ID. |
| `uint32` | CompressorID | Compression type. `0xB9F0B9EC` = Refpack, `0x0EAC15C8` = Uncompressed. |
| `int32` | DataSize | Size of the actual data. |
| `int32` | AllocSize | Size to allocate in memory. |
| `int32` | ReadSize | Size to read from disk (compressed size). |
| `int32` | ReadOffset | Offset in the file where data begins. |

## Chunk Structure

Inside the data area defined by the sections, data is organized into chunks.

| Type | Name | Description |
| --- | --- | --- |
| `uint16` | ChunkType | Identifier for the chunk type. |

**Known Chunk Types:**

* `0x10FB`: **Refpack Compressed Data**. (Header bytes `0x10 0xFB` are the Refpack signature).
* `0x1607`: **Embedded Asset**. Contains resources like MetaModels, Textures, etc.
* `0x2207`: **SimGroup**. Contains game object/entity definitions.
* `0x2307`: **Embedded Asset (Compact)**.
